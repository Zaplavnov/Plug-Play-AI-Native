# Integration — подключение приложения

Разработчик подключаемого приложения запускает интеграцию в панели платформы. Integration Agent на LangGraph управляет процессом от анализа исходных материалов до подготовки pull request (PR).

## Как проходит интеграция

1. **Подключить проект.** Разработчик указывает репозиторий и коммит, передаёт OpenAPI и документацию, задаёт URL тестового стенда и разрешённое окружение. Платформа фиксирует коммит и хеши входных материалов, чтобы результаты можно было связать с конкретной версией проекта.
2. **Найти возможности.** Платформа автоматически извлекает операции и схемы из OpenAPI и ищет связи с маршрутами, обработчиками и API-вызовами в React-коде. LLM может помочь описать назначение операции или предложить связь с интерфейсом. Панель показывает каталог кандидатов, их источники, предполагаемые эффекты и пробелы анализа.
3. **Проверить каталог и утвердить доступ.** Кандидат — потенциальное действие агента. Разработчик проверяет его описание и доказательства, например запись в OpenAPI или место вызова в коде. Затем он решает, включить ли действие, кому оно доступно и когда нужно подтверждение пользователя. Неутверждённые возможности остаются выключенными.
4. **Собрать и проверить интеграцию.** Платформа подготавливает версию конфигурации агента, реестр разрешённых инструментов и изменения для подключения React SDK, чата и, при необходимости, адаптера интерфейса. Платформа проверяет схемы, сборку и совместимость с API. В sandbox preview разработчик может проверить сценарии на тестовом стенде и посмотреть предлагаемые изменения.
5. **Принять PR и активировать агента.** Разработчик проверяет и сливает PR в свой репозиторий. Подготовленную версию агента активируют отдельным действием. После активации её конфигурацию использует [Application Agent Runtime](runtime.md).

## Что передаётся в Runtime

**Capability Manifest** — версионируемое машиночитаемое описание возможностей приложения и решений о доступе. Запись может содержать идентификатор действия, параметры, ссылку на операцию API, источник обнаружения, решение разработчика, требуемые права и условие подтверждения. Например, для действия «Изменить срок заявки» разработчик разрешает использование только при наличии права на запись и с подтверждением пользователя.

Из утверждённых и включённых возможностей платформа формирует **Tool Registry** — реестр инструментов с правилами их вызова. Runtime использует его вместе с активной конфигурацией приложения и политикой доступа.

Способ получения исходников, метод UI-анализа, формат manifest и устройство sandbox preview предстоит определить.
