# Runtime — работа агента

Пользователь открывает чат в подключённом React-приложении. Встроенный SDK передаёт сообщение в облачную платформу, а общий Application Agent Runtime запускает агента с активной конфигурацией этого приложения.

## Как обрабатывается запрос

1. **Проверить сессию.** Платформа определяет пользователя и проект, загружает активную версию настройки агента и подбирает доступные инструменты с учётом утверждённой политики, прав пользователя и окружения.
2. **Выбрать, как ответить.** Runtime использует LLM, чтобы понять запрос. Если деталей не хватает, агент задаёт уточняющий вопрос. Для справки по правилам он ищет разрешённые фрагменты документации (RAG) и отвечает со ссылками на источники. Актуальные данные, например состояние заявки, агент получает через API приложения.
3. **Проверить действие.** Если нужен вызов инструмента, модель предлагает действие и аргументы. Сервер проверяет их по схеме и политике. Если политика требует подтверждения, чат показывает пользователю, что именно будет сделано, и ждёт его решения.
4. **Выполнить вызов и вернуть результат.** Перед вызовом сервер повторно проверяет права и, при необходимости, подтверждение. Executor обращается к разрешённой операции, а API приложения проверяет доступ к данным и выполняет бизнес-логику. Чат получает события выполнения и показывает результат, который вернул API. Интерфейс может обновить экран через UI Bridge — адаптер, связывающий разрешённые команды агента с интерфейсом приложения.

## Пример — перенос срока заявки

Пользователь пишет «Найди мою последнюю заявку и перенеси срок на пятницу». Агент получает список доступных пользователю заявок, находит нужную и уточняет дату, если она неоднозначна. Затем чат показывает номер заявки и новую дату. Если пользователь подтверждает изменение и серверная проверка прав проходит, агент вызывает API, показывает итог и обновляет данные на экране. При отказе API чат сообщает об ошибке.

Разработчик [на этапе интеграции](integration.md) утверждает, какие действия агент может предлагать. Пользователь в чате подтверждает конкретное выполнение, когда этого требует политика. API приложения по-прежнему проверяет его права на операцию и на конкретную заявку.
